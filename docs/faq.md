# ChunkCarve（取方）常见问答（Q&A）与多色 3D 打印避坑指南

本文档汇总了使用 **ChunkCarve v1.0.3** 提取 Minecraft 存档并导入切片软件（Bambu Studio / OrcaSlicer / 创想云 Creality Print 等）进行多色 3D 打印时最常遇到的 10 个问题及标准解决办法。

---

### Q1：在游戏和 ChunkCarve 预览里方块颜色边界都是横平竖直的，为什么导入切片软件后颜色分界线变成了连续弯曲的波浪线？

**原因**：
将带贴图的 `GLB` 或 `OBJ` 拖入切片软件（如创想云、Bambu Studio）时，弹出的「导入模型 / 多色转换」窗口中有一个 **「光滑程度 / 平滑度（Smoothness）」** 参数，软件默认往往设为 **`10`**。该算法本意是用来平滑曲面手办或 3D 扫描模型的贴图锯齿，但作用在 Minecraft 方块上时，会把直角像素交界线强行拉扯成圆滑的弯曲弧线。

**解决方法**：
1. 在切片软件弹出的「导入模型」窗口右上角，找到 **「光滑程度」（或「平滑度」）**。
2. 将数值从默认的 `10` 手动改为 **`0`**（若软件限制最小值为 1 则填最小值）。
3. 点击旁边的 **「应用」** 按钮刷新左侧预览，确认地形、草方块和矿石的分界线恢复笔直直角后，再点击「确定」导入。

### Q2：模型导入切片软件后，为什么草方块侧面、覆雪草地或矿石表面会出现“一半白、一半原色”的三角形斜切锯齿边？

**原因**：
这是因为普通贴图模型与 3D 打印多色网格的底层表达方式不同：
- 在「标准（2 三角形/面）」导出模式下，每个正方形方块面只由 **2 个沿对角线分割的直角三角形** 组成。
- 切片软件将贴图转为多色耗材时，不会在一个三角形内部按贴图像素重新切碎网格，而是**按三角形顶点/面片采样颜色**。当一张方块贴图上半部分是白雪/绿草、下半部分是棕土，或者石头里嵌有矿石斑点时，颜色分界只能沿着三角形的 45° 对角斜边走，于是出现了刺眼的三角形斜切锯齿（而纯色方块如灰色混凝土因为整张贴图颜色一致，两个三角形同色，所以看起来没有三角形）。

**解决方法**：
在 ChunkCarve 右上角「导出」菜单中，将 **「网格细分」** 切换为：
- **`8×8 微网格（防斜切锯齿·推荐）`**：将每个面正交切分为 `8×8 = 64` 个小方格（在默认 `2mm/格` 比例下，单个微格仅 `0.25mm`，已小于常见 `0.4mm` 喷嘴线宽），肉眼锯齿基本完全消失，且导出速度快、文件适中，**适合绝大多数打印场景**。
- **`16×16 像素级（极致平整·耗时较久）`**：严格 `1:1` 对应原版 `16×16` 像素贴图网格，每个像素格拥有独立正交边界，彻底消灭任何斜切锯齿。适合小范围建筑特写或大比例（如 `4mm/格` 以上）精细打印。

### Q3：选择了 `16×16 像素级` 细分后，点击导出等待了很久还没弹出保存框，是程序卡死崩了吗？

**不是卡死！请务必耐心等待，不要刷新或关闭窗口。**

**原因详解**：
开启 `16×16` 细分意味着每一个暴露在外的方块表面都会从 2 个三角形裂变为 **512 个三角形（面数整整放大 256 倍）**！
- 举例：一个包含山地、树林和房屋的中等选区，标准模式下约有 6 万个面，秒级即可导出；而在 `16×16` 模式下会暴涨至 **1,500 万个以上三角形**。
- 后端需要完成千万级顶点的坐标插值、退化面过滤、空间字节去重焊接以及数十至上百 MB 二进制数据的打包。中等或偏大选区耗时 **数十秒至数分钟** 均属正常现象。
- ChunkCarve v1.0.3 会在屏幕上方实时显示 `（已耗时 Xs）` 计时提醒，并在全部字节生成校验无误后自动弹出另存为窗口（确保绝不留下 0 字节损坏空文件）。

**如何缩短等待时间（同时减轻切片软件卡顿）？**
1. **首选 `8×8 微网格`**：面数仅为 `16×16` 的四分之一，速度提升约 4 倍，实际打印成品几乎看不出区别。
2. **裁掉多余地下岩石**：展开底栏「范围与尺寸」，手动调高 `Y 高度` 的起始底界（没必要把地表以下几十层实心石头侧面也做 256 倍细分）。
3. **按需关闭装饰物**：如果不打算打印细小的杂草和火把，在导出菜单取消勾选「交叉面／贴图装饰」，可大幅削减面数。

### Q4：我的基地离世界出生点非常远（几千甚至几万格），在地图上拖半天找不到家怎么办？

**解决方法**：
ChunkCarve v1.0.3 在「1 选区」界面底栏左侧提供了 **「定位」快捷导航栏**：
1. **直接选玩家**：点击「定位」右侧下拉框，软件已自动读取单人 `level.dat` 与多人 `playerdata/*.dat` 中记录的全部玩家坐标，并匹配 `usercache.json` / `usernamecache.json` 显示玩家昵称（如 `👤 Steve (-2480, 1650)`）。选中玩家后点击 **「定位并框选」**，视野会立刻跳转到你角色下线的位置并自动框好 `3×3` 区块！
2. **输入坐标跳转**：如果你知道建筑坐标（在 Minecraft 游戏内按 `F3` 查看 `Block` 或 `XYZ`），直接在底栏的 `X`、`Z` 输入框填入数字，点击 **「跳转」** 或 **「定位并框选」** 即可精准直达。

### Q5：雪片（薄雪层）、讲台、活板门、砂轮、楼梯、半砖这些非完整方块，以及树叶，导出后是怎么处理的？比例对吗？

**已在 v1.0.3 中完美对齐修复**：
- **树叶等镂空贴图完整方块**：统一按 `1×1×1` 完整实心方块渲染与导出表面贴图。这样既保留了树冠完整的像素体积感，又避免了树叶内部产生数以万计无法打印和清支撑的悬空碎面。
- **雪片、讲台、活板门、砂轮、楼梯、台阶、栅栏等非完整方块**：严格按照 Minecraft 方块模型（BlockModel）定义的真实元素尺寸与世界坐标偏移量 `1:1` 缩放还原。例如一层薄雪会完整平铺在下方方块顶面（占满整格长宽、高度为 1/8 格），讲台、活板门与砂轮也都处于各自准确的方位与比例，不会缩小偏居一角。

---

### Q6：草丛、花朵、火把、麦田这些十字交叉贴图方块能打印出来吗？能关掉吗？

- **默认开启**：导出菜单默认勾选 **「交叉面／贴图装饰（草、火把等）」**。程序会读取贴图的不透明像素轮廓并拉伸成具有物理厚度的薄片实体，使其不仅能在预览中看到，也能被切片软件识别。
- **打印建议**：如果你的打印比例较小（例如 `1 ~ 2 mm/格`），火把或草叶的实际厚度可能不足 `0.2mm`，低于常规 `0.4mm` 喷嘴的最小线宽，切片时可能变成零散挤出点或易断毛刺。此时建议**取消勾选「交叉面／贴图装饰」**，预览与导出的 `GLB` / `OBJ` 会自动剔除这些软装饰，同时完整保留楼梯、台阶、栅栏等建筑实体结构。

### Q7：导入切片软件时提示“项目最多支持 64 个耗材，多余的耗材将被丢弃”或颜色槽位太多怎么办？

**原因**：
Minecraft 贴图（尤其加了模组后）包含成百上千种细微过渡色值，而切片软件单项目最多支持 64 种颜色槽位，实际物理多色供料系统通常为 4 色、8 色、16 色或 CMYW 四色混色。

**解决方法**：
在切片软件的「导入模型」弹窗中：
1. 在右上角 **「颜色数目」** 中点击预设的 `4`、`8`、`16`（或根据你的多色系统设定数值），再把「光滑程度」设为 `0`，点击 **「应用」**。
2. 勾选下方的 **「自动合并相同的耗材」**，并将相近色块映射到你实际装载的耗材槽位。
3. 若你使用的是单台 4 色 / 双台 8 色 AMS 且不想调贴图映射，也可以在 ChunkCarve 导出时直接选择 **`3MF · AMS 多色`（4 色 / 8 色）** 格式。

### Q8：选择 OBJ 格式导出后，把 `.obj` 拖进软件为什么全是白色的、没有颜色贴图？

**原因**：
OBJ 格式本身不能内嵌图片，ChunkCarve 导出的是一个包含 `.obj`（几何）、`.mtl`（材质索引）和 `textures/*.png`（贴图图片）的 **`.zip` 压缩包**。如果直接在压缩包预览窗口里把 `.obj` 单独拖出来，软件找不到同目录下的 `.mtl` 和 `.png`，就会变成白模。

**解决方法**：
- **方法 A（推荐）**：直接改用 **`GLB · 内嵌贴图`** 格式导出，单文件自带全部贴图，拖入即有色。
- **方法 B**：先把导出的 `.zip` 完整解压到一个普通文件夹中，保持文件夹内所有文件相对位置不变，再从解压后的文件夹中把 `.obj` 导入软件。

---

### Q9：新建项目选择 `versions` 目录后，为什么没看到我的整合包存档或模组方块缺贴图？

**原因与解决方法**：
当开启了启动器“版本隔离”（PCL2、HMCL 常见设置）时，存档与 `mods` 存放在 `versions/<具体整合包名>/` 子目录下，而不是 `.minecraft` 根目录。
1. 在「新建项目」中选择 `.minecraft` 或 `versions` 目录后，请留意下方出现的 **「检测到的版本实例」** 下拉框。
2. 从下拉框中手动选中你要渲染的具体整合包名称（如 `元素觉醒1.4.6`）。
3. 等待下方的 `版本 Jar`、`模组`、`材质包` 三个状态标签完成刷新并列出该整合包专属存档后，再点选存档保存。

### Q10：Windows 双击无法启动或浏览器访问失败如何排查？

1. **绿色免安装版启动检查**：请确保已将 `ChunkCarve-v1.0.3-win64.zip` **完整解压**，不要在压缩软件内直接双击 `ChunkCarve.exe`，也不要把 `ChunkCarve.exe` 单独移出所在目录（它依赖同目录的 `_internal` 运行库）。
2. **报错 `Failed to resolve Python.Runtime.Loader.Initialize`**：这表示程序所需的 `.NET` 组件未能加载。Windows 可能给从网络下载的 ZIP 加上来源安全标记，部分解压工具会把标记传给其中的 DLL，导致 `.NET` 拒绝加载。请先关闭程序，右键**原 ZIP 压缩包** → **「属性」** → 勾选 **「解除锁定」** → **「应用」**，然后**重新解压到一个新文件夹**再运行。

   已经解压的用户，也可以在 PowerShell 中执行以下命令（将示例路径替换为实际包含 `ChunkCarve.exe` 和 `_internal` 的程序文件夹）：

   ```powershell
   Get-ChildItem -LiteralPath "D:\Apps\ChunkCarve" -Recurse -File | Unblock-File
   ```

   执行后重新打开 `ChunkCarve.exe`。下载来源标记与杀毒软件报毒是两回事；如果解除锁定后仍报错，请检查 `_internal\pythonnet\runtime\Python.Runtime.dll` 是否完整、是否被隔离，并附上日志反馈。

3. **WebView2 运行时**：桌面独立窗口依赖 Windows 10/11 系统自带的 Microsoft Edge WebView2。若极少数精简版系统缺失 WebView2，可安装微软官方 WebView2 Runtime，或在源码环境下运行 `py -m mcmap.server` 使用 Chrome / Edge 浏览器访问 `http://127.0.0.1:8770/`。
4. **提交诊断信息**：如遇异常，可查看程序目录下的 `desktop_error.log`，或在软件左上角存档下拉菜单底部点击 **「复制诊断信息」**，贴到 [GitHub Issues](https://github.com/Cangminghai/chunkcarve/issues) 或 [Discussions](https://github.com/Cangminghai/chunkcarve/discussions) 中反馈。
